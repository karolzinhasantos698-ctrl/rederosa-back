Check-in Seguro com acompanhamento
Data: ____________________     Participantes: ______________________________
Descrição das atividades — O check-in passou a permitir acompanhamento com prazo de 15, 30 ou 60 minutos. A usuária escolhe com quem compartilhar o link. Com a permissão de localização, o mapa mostra a posição mais recente.

Banco de dados e publicação
Configuração do banco e testes do backend
Data: ____________________     Participantes: ______________________________
Descrição das atividades — O backend Spring Boot foi configurado para acessar o banco MySQL rederosa no Aiven via JDBC com TLS. As credenciais são fornecidas pela configuração do ambiente.
Resultados e encaminhamentos — A primeira tentativa falhou porque as credenciais do console do IntelliJ não estavam disponíveis para o Spring. Após configurar o ambiente, a aplicação iniciou e a consulta confirmou nove tabelas. Em uma execução registrada da suíte Maven, os 30 testes passaram.
Lições aprendidas — O console de banco e o Spring usam configurações independentes. Os testes com H2 permitem verificar o backend sem depender do Aiven.
Publicação e integração do frontend
Data: ____________________     Participantes: ______________________________
Descrição das atividades — A API foi publicada no Render e o frontend na Vercel. O arquivo js/api.js foi ajustado para usar a URL pública do Render no domínio da Vercel.
Resultados e encaminhamentos — A primeira publicação carregava a tela, mas as chamadas ainda iam para o próprio domínio da Vercel. O ajuste foi aplicado à branch de produção do repositório ligado à Vercel e, após a publicação, o login chegou à página inicial autenticada.
Lições aprendidas — Publicar a interface e conectá-la à API são etapas distintas. A atualização precisa chegar ao repositório que a Vercel acompanha.
