Arquivos e API no mesmo domínio

O Nginx entrega o frontend e encaminha caminhos de API para o Java. Isso simplifica as URLs do navegador.

Integrações externas

O Java pode chamar serviços de IA, e-mail ou mapas. Esses serviços têm credenciais e limites próprios.

Uma única VM facilita o início, mas uma falha nela afeta frontend, backend e banco juntos.

05 · Assinatura Azure

Crédito, cota e disponibilidade são diferentes.

1. Crédito

Saldo disponível e data de vencimento. Ter dinheiro na assinatura não libera automaticamente todos os recursos.

2. Política de região

Define onde a assinatura permite implantar. Consultar Política → Atribuições → Parâmetros.

3. Cota de CPU

Conferir o limite regional e o limite da família de VM em Cotas → Compute.

4. Disponibilidade

O tamanho precisa estar realmente implantável para aquela assinatura, região e configuração.

NotAvailableForSubscription e “cota insuficiente” não são o mesmo problema. Conferir o erro antes de trocar o tamanho.
06 · Dimensionamento e custo

Escolha pela carga, confirme pelo teste.

CenárioPonto de partida para avaliar
Protótipo e pouco acesso2 vCPUs e 4 GiB de RAM
Mais espaço para Java e MySQL2 vCPUs e 8 GiB de RAM
Competição ou uso simultâneo elevadoTeste de carga antes de definir capacidade

Cadastros ≠ simultaneidade

Mil contas ao longo do mês podem pesar menos que muitas pessoas consultando o chat e o GPS ao mesmo tempo.

Custo total

VM + disco + IP + tráfego + backups + serviços extras. API externa pode ser cobrada fora do Azure.

RAM não é espaço de disco. Série B tem créditos de CPU; avaliar carga sustentada. Preço e disponibilidade devem ser conferidos no portal.

07 · Criar a VM

Configuração inicial no portal.

Básico

  • Assinatura e grupo exclusivos do projeto.
  • Região autorizada com cota e tamanho disponível.
  • Ubuntu Server 24.04 LTS, arquitetura x64.
  • Chave pública SSH; usuário azureuser.
  • Spot desativado para evitar retomada de capacidade.

Disco e rede

  • SSD Standard LRS; 30–32 GiB para avaliar inicialmente.
  • Disco persistente para guardar o MySQL.
  • IP público estático e grupo de segurança.
  • Sem balanceador para esta arquitetura simples.
  • Revisar preço, validação e ciclo de exclusão dos recursos.
Para uma VM simples, “sem redundância de infraestrutura” pode ampliar opções, mas não resolve uma cota zero nem oferece alta disponibilidade.

09 · SSH

Saiba em qual computador está executando.

PowerShell do Windows

ssh -i "$env:USERPROFILE\Downloads\vm-meuprojeto_key.pem" azureuser@IP_PUBLICO

Usado para conectar, compilar localmente e enviar arquivos com scp.

Terminal Ubuntu

azureuser@vm-meuprojeto:~$

Instala pacotes e configura banco, Nginx e serviços. Após uma queda do SSH, reconecte antes de continuar.

  • Não copie o prefixo do terminal junto com o comando.
  • Verifique a identidade do servidor na primeira conexão.
  • Proteja o arquivo .pem; não o envie ao Git ou ao chat.
  • Se a chave for recusada por permissões abertas, ajuste a ACL no Windows conforme o guia.
10 · Dependências

Instale e valide cada serviço.

# Ubuntu: executar uma linha por vez
sudo apt update
sudo apt install -y openjdk-17-jre-headless mysql-server nginx python3
sudo systemctl enable --now mysql nginx
java -version
sudo systemctl is-active mysql nginx

Resultado esperado

Java na versão exigida pelo projeto e duas linhas active, uma para MySQL e outra para Nginx.

Erro comum

apt update atualiza o catálogo, mas não instala os programas. É necessário executar apt install.

Se o projeto exige Java 21 ou outra versão, ajuste o pacote e valide a compatibilidade do JAR.

11 · MySQL

Banco próprio, usuário próprio.

# Ubuntu
sudo mysql -e "CREATE DATABASE IF NOT EXISTS meuprojeto CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
sudo env MYSQL_HISTFILE=/dev/null mysql
-- Dentro do MySQL; substituir a senha antes de executar
CREATE USER 'meuprojeto_app'@'localhost' IDENTIFIED BY 'SENHA_FORTE';
GRANT ALL PRIVILEGES ON meuprojeto.* TO 'meuprojeto_app'@'localhost';
EXIT;
# Ubuntu: digitar a senha no prompt
mysql -u meuprojeto_app -p -D meuprojeto -e "SELECT 1;"
Esperado: retorno 1. As permissões acima permitem gerenciar a estrutura desse banco; reduzir privilégios quando houver migrações separadas. Não usar root no backend.
12 · Build

Gere um artefato testado antes de enviar.

# PowerShell no Windows
cd C:\CAMINHO\backend
.\mvnw.cmd clean package

Prossiga com BUILD SUCCESS

O Maven compila, testa e empacota. Envie o JAR executável de target, não o arquivo .jar.original.

Teste dependente de banco local

Corrigir a configuração isolada do teste quando adequado. Não ignorar testes automaticamente para publicar.

scp -i "$env:USERPROFILE\Downloads\vm-meuprojeto_key.pem" "C:\CAMINHO\backend\target\ARQUIVO.jar" azureuser@IP_PUBLICO:/home/azureuser/backend-next.jar
13 · Separação de permissões

O processo Java não precisa ser administrador.

# Primeira configuração, no Ubuntu
sudo useradd --system --user-group --home-dir /opt/meuprojeto --shell /usr/sbin/nologin meuprojeto
sudo install -d -o root -g meuprojeto -m 0750 /opt/meuprojeto
sudo install -d -o root -g root -m 0700 /etc/meuprojeto
sudo install -o root -g meuprojeto -m 0640 /home/azureuser/backend-next.jar /opt/meuprojeto/backend.jar
O usuário meuprojeto executa a aplicação e lê o JAR, mas não altera o código. O administrador SSH continua sendo azureuser.

Se o projeto grava arquivos, crie um diretório próprio para dados e conceda permissão somente nele. Confira usuários e diretórios existentes antes de repetir a configuração.

14 · Variáveis de ambiente

Configuração privada, fora do código.

sudo nano /etc/meuprojeto/backend.env
SPRING_DATASOURCE_URL=jdbc:mysql://localhost:3306/meuprojeto
SPRING_DATASOURCE_USERNAME=meuprojeto_app
SPRING_DATASOURCE_PASSWORD="SENHA_REAL"
SERVER_ADDRESS=127.0.0.1
SERVER_PORT=8080
SERVER_FORWARD_HEADERS_STRATEGY=framework
SPRING_JPA_SHOW_SQL=false

Salvar: Ctrl+O → Enter → Ctrl+X.

sudo chmod 600 /etc/meuprojeto/backend.env

Acrescente somente integrações que o código realmente lê, por exemplo GROQ_API_KEY. Nunca coloque segredos no frontend.

Esse arquivo não é um script: não usar export nem esperar expansão automática de variáveis. Escapar aspas e barras quando necessário.

15 · Persistência do banco

Escolha como as tabelas serão evoluídas.

Migrações controladas

Flyway ou Liquibase registram alterações versionadas. Hibernate em validate pode conferir a estrutura.

É preciso que o projeto já esteja preparado para essa estratégia.

Protótipo com Hibernate update

spring.jpa.hibernate.ddl-auto=update pode criar e ajustar tabelas. Faça backup antes de alterar entidades.

Não é uma estratégia completa de migração e rollback.

Não usar create ou create-drop no banco persistente de produção: a estrutura e os dados podem ser recriados ou apagados.

Banco novo começa vazio. Criá-lo não importa os cadastros do computador de desenvolvimento.

16 · systemd

Transforme o JAR em serviço.

# /etc/systemd/system/meuprojeto.service
[Unit]
Description=Backend Meu Projeto
After=network.target mysql.service
Requires=mysql.service

[Service]
User=meuprojeto
Group=meuprojeto
WorkingDirectory=/opt/meuprojeto
EnvironmentFile=/etc/meuprojeto/backend.env
ExecStart=/usr/bin/java -Xms128m -Xmx1g -jar /opt/meuprojeto/backend.jar
Restart=on-failure
RestartSec=5
UMask=0077
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target

Por que usar?

  • Continua funcionando após sair do SSH.
  • Inicia com a máquina.
  • Reinicia após falha.
  • Centraliza os logs.
sudo systemctl daemon-reload
sudo systemctl enable --now meuprojeto
sudo systemctl status meuprojeto --no-pager -l

-Xmx1g limita o heap, não toda a memória do processo Java.

17 · Frontend

Localhost não é o servidor para o visitante.

Endereço incorreto em produção

fetch('http://localhost:8080/api/usuarios')

O navegador tenta acessar o próprio computador ou celular da pessoa.

Mesma origem do site

fetch('/api/usuarios')

O navegador chama o domínio HTTPS atual, e o Nginx encaminha à API.

  • Revisar URLs, portas e configuração de base da API no código fonte.
  • Enviar somente HTML, CSS, JS, imagens ou a saída estática do build.
  • Não publicar .env, .git, dumps ou chaves.
React/Vue podem gerar arquivos estáticos. Aplicações com renderização no servidor exigem outro processo e ajustes neste roteiro.
18 · Publicação do frontend

Envie, confira a estrutura e publique.

# PowerShell
scp -i "$env:USERPROFILE\Downloads\vm-meuprojeto_key.pem" -r "C:\CAMINHO\frontend" azureuser@IP_PUBLICO:/home/azureuser/frontend-inicial
# Ubuntu
find /home/azureuser/frontend-inicial -maxdepth 3 -name index.html
sudo install -d -m 0755 /var/www/meuprojeto
sudo cp -a /home/azureuser/frontend-inicial/. /var/www/meuprojeto/
sudo chown -R root:root /var/www/meuprojeto
sudo find /var/www/meuprojeto -type d -exec chmod 755 {} +
sudo find /var/www/meuprojeto -type f -exec chmod 644 {} +
Confirme que o resultado é /var/www/meuprojeto/index.html. Uma subpasta inesperada ou uma cópia não executada é causa frequente de 404.
19 · Nginx

Um domínio, dois destinos.

# /etc/nginx/sites-available/meuprojeto
server {
    listen 80;
    server_name DOMINIO;
    root /var/www/meuprojeto;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }
}

Adapte às rotas reais

O exemplo encaminha /api/. Rotas como /login e /chat precisam de blocos adicionais se existirem.

Sem barra após 8080, o prefixo da API é preservado.

SPA, WebSocket, SSE e uploads exigem ajustes específicos.

20 · Validar proxy

Teste antes de abrir o navegador.

sudo ln -sfn /etc/nginx/sites-available/meuprojeto /etc/nginx/sites-enabled/meuprojeto
sudo nginx -t
# Recarregar somente se a validação passar:
sudo systemctl reload nginx

curl -I -H 'Host: DOMINIO' http://127.0.0.1/
curl -i -H 'Host: DOMINIO' http://127.0.0.1/api/ENDPOINT_REAL
ResultadoO que investigar
200 com conteúdo esperadoEssa rota respondeu; continuar os testes funcionais.
404Arquivo, caminho, domínio ou rota incorreta.
502Backend parado, iniciando ou porta errada.
21 · DNS e HTTPS

Do IP ao endereço seguro.

  1. No recurso de IP público, escolha um rótulo DNS disponível e salve.
  2. Copie o nome completo mostrado pelo Azure; não adivinhe o sufixo.
  3. Configure esse nome no server_name do Nginx.
  4. Confirme DNS e acesso HTTP antes de emitir o certificado.
getent ahostsv4 DOMINIO
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d DOMINIO --redirect
Informe um e-mail de contato e avalie os termos. O Certbot configura TLS e redirecionamento, mas a porta 443 precisa estar liberada na rede.
22 · Certificado

Emitir é o começo; renovar faz parte.

sudo nginx -t
curl -I https://DOMINIO/
sudo certbot renew --dry-run
systemctl list-timers --all | grep -i certbot

Teste externo falhou?

curl -I --resolve DOMINIO:443:127.0.0.1 https://DOMINIO/

Se funcionar localmente, investigar rede, DNS e firewall antes de reemitir certificados.

Cuidados

  • Manter a validação HTTP acessível conforme a configuração.
  • Não sobrescrever o arquivo TLS com uma versão antiga.
  • Não divulgar a chave privada do certificado.
23 · Testes e diagnóstico

Isole as camadas, sem adivinhar a causa.

EtapaTesteO que acrescenta
1. Backendhttp://127.0.0.1:8080/api/...Java e dependências da aplicação
2. Proxy localNginx local com cabeçalho HostRoteamento do Nginx
3. HTTPS públicohttps://DOMINIO/api/...DNS, TLS e caminho público
4. NavegadorDevTools → Network → requisiçãoURL, status, resposta e tempo
Um cancelamento exato após 25 segundos pode revelar o limite do frontend; ele não prova que login, chave ou banco causaram a demora. Repetir testes comparáveis e medir.

Alterar uma coisa por vez. Guardar evidências antes de mudar modelo, timeout, infraestrutura ou credenciais.

24 · Checklist funcional

Teste o comportamento que o usuário precisa.

  • Página inicial, imagens e navegação.
  • Cadastro e login.
  • Permissões entre contas diferentes.
  • Persistência após reiniciar o serviço.
  • API sem localhost ou conteúdo misto.
  • Integrações e erros do provedor.
  • Links compartilhados em outro aparelho.
  • GPS em HTTPS, se existir.
  • Recuperação de senha segura.
  • Uso após fechar o terminal SSH.
  • Comportamento sob carga.
  • Proteção dos arquivos privados.
Usar dados fictícios. Uma resposta HTTP 200 isolada não equivale a validar o sistema inteiro.
25 · Atualizações

Atualize com possibilidade de recuperação.

Backend

  1. Executar build e testes.
  2. Enviar JAR com nome temporário.
  3. Fazer backup quando houver risco de mudança de banco.
  4. Guardar JAR anterior e parar o serviço.
  5. Instalar novo JAR e iniciar.
  6. Validar endpoint e logs.

Frontend e configuração

  • Enviar para pasta nova e conferir estrutura.
  • Guardar versão publicada antes da troca.
  • Revisar arquivos antigos que não deveriam permanecer públicos.
  • Alterou .env? Reiniciar o backend.
  • Alterou .service? Executar daemon-reload e reiniciar.
Não sobrescrever um JAR em uso. Voltar o JAR anterior não desfaz alterações de schema ou dados.
26 · Backup

Uma cópia no mesmo disco não basta.

# Ubuntu
mkdir -p ~/backups
chmod 700 ~/backups
(umask 077; sudo mysqldump --single-transaction --no-tablespaces --databases meuprojeto > ~/backups/meuprojeto-$(date +%Y%m%d-%H%M%S).sql)

Verificar

Comando sem erro, arquivo não vazio e dados esperados. Não alterar schema durante o dump.

Externalizar

Guardar cópia protegida fora da VM. Dumps podem conter dados pessoais.

Restaurar

Testar recuperação em ambiente isolado. Backup não testado deixa incerteza.

Guardar também configurações e versões dos artefatos. Confirmar alvo e backup antes de DROP, TRUNCATE ou importações destrutivas.

27 · Operação

Os comandos para acompanhar a aplicação.

Saúde e logs

sudo systemctl status meuprojeto --no-pager -l
sudo journalctl -u meuprojeto -n 100 --no-pager
sudo journalctl -u meuprojeto -f
sudo tail -n 50 /var/log/nginx/error.log

Ctrl+C encerra a leitura dos logs, não o serviço.

Memória, disco e portas

free -h
df -h /
sudo du -sh /var/lib/mysql /var/www/meuprojeto
sudo journalctl --disk-usage
sudo ss -lntp

Logs podem conter informações pessoais. Revisar antes de compartilhar.

Estabeleça alertas e revisão periódica de saldo, vencimento de créditos e uso real. Orçamento não é necessariamente um bloqueio automático de cobrança.
28 · Entrega

O que significa estar pronto?

Operação validada

  • Serviço inicia automaticamente.
  • API e frontend funcionam por HTTPS.
  • Banco tem usuário exclusivo.
  • Fluxos e autorização testados.
  • Capacidade avaliada conforme uso esperado.

Continuidade planejada

  • Segredos privados e credenciais expostas revogadas.
  • SSH restrito e portas mínimas.
  • Backup externo com restauração testada.
  • Renovação de certificado validada.
  • Atualização, rollback e custos documentados.

Cada projeto precisa adaptar rotas, variáveis, versão do Java e estratégia de banco. O roteiro é reutilizável; a validação precisa ser específica.
